# RusGuard Importer

Единое приложение: добавление ключей существующим сотрудникам и создание новых профилей в RusGuard (PostgreSQL), с необязательным созданием Access-базы карточек напрямую из данных БД.

## Структура проекта

```
src/            код (app.py — GUI, importer.py — импорт, db.py, sheets.py, keys.py, access_export.py, settings.py)
templates/      template_add.xlsx, template_new.xlsx, template.accdb
data/           рабочие файлы и настройки в Docker (создаётся автоматически)
Dockerfile, docker-compose.yml, importer.sh   запуск в Linux
importer.bat, requirements.txt                запуск в Windows
```

## Запуск в Linux (Docker)

```bash
./importer.sh            # скачивает и запускает severnbli/rusguard-importer:latest
./importer.sh --build    # собрать образ локально из исходников
```

Без клонирования репозитория достаточно образа:

```bash
mkdir -p data && xhost +SI:localuser:$USER
docker run --rm --network host -e DISPLAY=$DISPLAY -e HOME=/data --user $(id -u):$(id -g) \
  -v /tmp/.X11-unix:/tmp/.X11-unix -v "$PWD/data:/data" severnbli/rusguard-importer:latest
```

Нужны Docker с compose-плагином и X-сервер (для Wayland — XWayland). Скрипт разрешает контейнеру доступ к X-серверу через `xhost` (пакет `xorg-xhost`/`x11-xserver-utils`; если его нет — выполните `xhost +SI:localuser:$USER` самостоятельно).

- Папка `data/` в корне проекта монтируется в контейнер как `/data`: там лежат настройки (`data/.config/rusguard-importer/settings.json`), а рабочие Excel-файлы и фото нужно хранить в ней, чтобы они были видны в окнах выбора файлов.
- Шаблоны уже находятся внутри образа.
- Внутри контейнера нет Excel-редактора: после «Создать из шаблона…» откройте созданный файл из `data/` на хосте сами.
- Контейнер использует сеть хоста, поэтому PostgreSQL доступен так же, как с хоста.
- Access-экспорт в Linux недоступен (в интерфейсе отключён).

## Запуск в Windows

`python -m venv venv && venv\Scripts\pip install -r requirements.txt`, затем `importer.bat` в корне проекта. Для Access-экспорта нужен драйвер «Microsoft Access Driver (*.mdb, *.accdb)» той же разрядности, что и Python.

### Сборка .exe

Готовый `RusGuardImporter.exe` собирает GitHub Actions (workflow `Build Windows exe`, артефакт `RusGuardImporter-windows`; при пуше тега `v*` файл прикрепляется к релизу). Локально, на Windows:

```bat
venv\Scripts\pip install pyinstaller
venv\Scripts\pyinstaller --noconfirm --onefile --windowed --name RusGuardImporter --paths src --add-data "templates;templates" src\app.py
```

Результат — `dist\RusGuardImporter.exe`. Настройки хранятся отдельно (`%APPDATA%\rusguard-importer`), драйвер Access в `.exe` не входит.

## Настройки (вкладка «Настройки»)

Хост, порт, база, пользователь, пароль, таблица Access, размер фото, регистр должности, формат ключей по умолчанию. Хранятся в `%APPDATA%\rusguard-importer\settings.json` (Linux: `~/.config/rusguard-importer/settings.json`), пароль — открытым текстом. Кнопка «Проверить подключение» проверяет доступ к БД.

Должности и группы приложение берёт с сервера (`employeeposition.name`, `employeegroup.name`).

## Работа

Данные вводятся в таблице внутри приложения; Excel необязателен.

1. Выберите режим (создание, редактирование, Access-база) и формат ключей.
2. **Создание профиля:** «Добавить строку», затем ФИО, ключ(и), Должность и Группа (выпадающие списки с данными сервера; «Обновить списки» перечитывает их).
   **Редактирование профиля:** «Найти в БД…» — поиск по ФИО или номеру ключа либо выбор группы целиком («Показать сотрудников», «Выделить всех»); при выборе строки показывается фото сотрудника. «Очистить таблицу» удаляет все строки. Форма та же, что при создании, но заполнена данными из БД: ФИО, текущие ключи (в поле через запятую, в выбранном формате), должность, группа, фото. Сотрудник определяется по id из БД, а не по ФИО, поэтому ФИО можно менять. Поле ключей — полный список: добавленные номера назначаются, удалённые снимаются (назначение удаляется из `acskey2employeeassignment`). В БД записываются только изменённые поля; «Откатить к данным из БД» возвращает строку к исходному состоянию.
3. «Выбрать фото…» открывает диалог обрезки: формат (3:4, 1:1, 4:3, 2:3, 3:2, 4:5, 5:4, 9:16, 16:9), перетаскивание мышью, масштаб колесом или ползунком, «Без обрезки». Результат — JPEG с заданной максимальной стороной (Настройки → «Макс. сторона фото»). Последний выбранный формат запоминается.
4. «Из Excel…» добавляет в таблицу строки из xlsx (столбцы ФИО, Ключ, а для нового профиля ещё Должность, Группа); «Шаблон Excel…» сохраняет заготовку (для нового профиля — с выпадающими списками). Фото к строкам из Excel добавляются вручную кнопкой «Выбрать фото…».
5. «Импортировать».

- Несколько ключей в одной ячейке разделяются `,` `;` `/` или переносом строки.
- Строка с ФИО, начинающимся на `#`, пропускается.
- Формат ключей: десятичный, HEX, HEX с обратным порядком байт (`04A1B2C3` → `C3B2A104`). Допустимы префикс `0x` и разделители `:` `-` `_` пробел; значение должно помещаться в знаковый bigint и быть ненулевым.
- Фото записывается в `employeephoto` в той же транзакции; у существующего сотрудника заменяется текущее фото №1.
- Режим «Access-база» (только Windows): через «Найти в БД…» (по ФИО, ключу или группе) добавляются сотрудники, данные только для просмотра. Кнопка «Создать Access-базу…» копирует `templates/template.accdb` и заполняет её карточками (ФИО, должность, фото) из БД.
- По умолчанию «всё или ничего»: при любой проблеме в БД не сохраняется ничего.
