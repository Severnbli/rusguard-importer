# Графические оболочки (GUI)

`rusguard_gui.py` и `access_gui.py` — окна поверх уже существующих
консольных скриптов. Они ничего не дублируют и не меняют в логике
импорта: просто собирают введённые в форму значения в те же аргументы
командной строки и запускают `rusguard.py` / `access.py`
как отдельный процесс, показывая его вывод построчно в реальном времени.
Если что-то работало через консоль — так же будет работать и через GUI
(включая режим «всё или ничего», `--dry-run` и коды возврата).

## Установка и запуск

`tkinter` — часть стандартной библиотеки Python, отдельно ставить не
нужно (в официальном установщике с python.org уже есть). Нужны только
обычные зависимости самих скриптов (`requirements.txt` /
`requirements_access.txt`).

Все `.py`-файлы должны лежать **в одной папке**:
`common.py` + `rusguard.py` + `gui_common.py` + `rusguard_gui.py` для
одного окна, `common.py` + `access.py` + `gui_common.py` + `access_gui.py`
— для другого. Проще всего держать все шесть в одной папке — они друг
другу не мешают (`common.py` — общая часть консольных скриптов,
`gui_common.py` — общая часть окон, это два разных файла).

```bash
python rusguard_gui.py
python access_gui.py
```

На Windows, если не нужна консоль рядом с окном, можно запускать через
`pythonw.exe rusguard_gui.py`.

## Что есть в окне

- Поля формы — те же, что у флагов командной строки (подсказки в
  скобках повторяют название флага, если оно отличается от подписи).
- **Пароль** (только у `rusguard_gui.py`) — передаётся дочернему
  процессу через переменную окружения `PGPASSWORD`, а не аргументом
  командной строки, поэтому не виден в списке процессов. Рядом —
  чекбокс «показать», чтобы проверить, что ввели правильно.
- **Запустить** — стартует процесс, блокирует повторный запуск, пока
  этот не закончится.
- **Остановить** — принудительно прерывает ещё выполняющийся процесс
  (`terminate()`).
- **Сохранить лог…** — сохраняет то, что сейчас показано в текстовом
  поле, в `.txt`-файл (удобно приложить при обращении за помощью).
- Строка статуса под кнопками окрашивается по итоговому коду возврата:
  зелёный (0, всё сохранено), жёлтый/оранжевый (2, есть проблемы или
  ничего не сохранено — подробности в логе), красный (1 или иное — не
  удалось даже начать).

## Чего в GUI сознательно нет

Это тонкая обёртка, а не отдельный инструмент: она не проверяет данные
сама, не парсит Excel и не подключается к БД/Access напрямую — всё это
по-прежнему делает соответствующий `.py`-скрипт. Если нужно что-то, чего
нет в форме (редкий флаг, отладка), тот же результат всегда можно
получить, запустив скрипт из консоли напрямую — см. `README.md` /
`README_access.md`.

## gui_common.py

Общая часть для обеих оболочек: панель лога с потоковым выводом (через
очередь, поток чтения stdout процесса отделён от потока интерфейса Tk),
обёртка над `subprocess.Popen` (кодировка дочернего процесса всегда
принудительно UTF-8, чтобы кириллица не превращалась в “кракозябры” из-за
системной кодовой страницы Windows), и набор общих полей формы (Excel-
файл, лист-справочник должностей, папка с фото, `--only-page`/
`--only-person`, три чекбокса, кнопки, статус-строка). `rusguard_gui.py`
и `access_gui.py` наследуются от одного базового класса и добавляют
только свои специфичные поля (подключение к БД / файл Access).
