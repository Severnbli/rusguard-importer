# access.py

Самостоятельный скрипт: добавляет ФИО, Должность и Фото из Excel в Access
(`карточки.accdb`). Не зависит от `rusguard.py` и от Postgres —
запускается отдельно. Формат исходного Excel — тот же, что у
`rusguard.py` (см. основной `README.md`), но нужны только часть
столбцов и другой лист-фильтр.

## Установка

```bash
pip install -r requirements_access.txt
```

`access.py` использует общий модуль `common.py` (тот же, что и у
`rusguard.py`) — он должен лежать **в той же папке**.

Плюс на машине должен быть установлен драйвер **"Microsoft Access Driver
(*.mdb, *.accdb)"** (Microsoft Access Database Engine Redistributable) —
только Windows; разрядность (32/64-бит) должна совпадать с разрядностью
Python.

## Что нужно от Excel

Лист-справочник должностей (по умолчанию `Должности`, см.
`--sheet-positions`) этим скриптом **не читается** — используется только
его имя, чтобы не принять за страницу с людьми.

На каждой из остальных страниц нужны столбцы: **№**, **ФИО**,
**Должность**, **Карточка изготовлена** (`Да`/`Нет`), и опционально
**Путь к фото** (одно значение на всю страницу, см. основной README про
абсолютные/относительные пути и именование файлов `<№>.<расширение>`).
Столбцы **Айди группы**/**Карточка в системе**/**Номер карты** этому
скрипту не нужны и игнорируются.

ФИО, начинающееся с `#`, пропускается целиком (закомментированная строка).

## Что делает

Добавляет в указанную Access-таблицу (по умолчанию `Export`) **новые**
записи: **[ФИО]**, **[Должность]**, **[Фото]** — только для строк, где
**Карточка изготовлена = Нет**.

- **[Должность]** пишется как текст из Excel, **без сверки со
  справочником** (в Access нет Id должности). По умолчанию приводится к
  нижнему регистру — как в уже существующих записях образца (`учитель`,
  а не `Учитель`). Флаг `--access-position-case asis` пишет как в Excel.
- **[Фото]** — конвертируется в BMP и оборачивается в тот же OLE-формат,
  что у существующих записей (см. ниже).

## Чего не делает

Только **добавление новых** записей. Если ФИО уже есть в Access —
строка целиком пропускается: ни фото, ни должность, ничего для неё не
меняется.

## Запуск

```bash
# проверка "на сухую"
python access.py import.xlsm "C:\путь\карточки.accdb" \
    --photos-root "C:\Data" --dry-run

# реальное добавление
python access.py import.xlsm "C:\путь\карточки.accdb" \
    --photos-root "C:\Data"

# только одна страница / один человек
python access.py import.xlsm "C:\путь\карточки.accdb" \
    --photos-root "C:\Data" --only-page "2А" --only-person 5
```

Оба пути (Excel, `.accdb`) обязательны и позиционные. `--only-person` без
`--only-page` — ошибка. Полный список параметров:
`python access.py --help`.

## Режим «всё или ничего» (по умолчанию)

Если хотя бы одна **подлежащая добавлению** строка не проходит проверку
(пустой Fullname, повторяющееся ФИО в файле, которого ещё нет в Access —
тогда неясно, чьё фото/должность использовать) — **в Access не
добавляется вообще ничего**. `--allow-partial` отключает это.

## Формат поля [Фото]

Реверс-инжинирен по 66 реальным записям присланного образца — обычная
Access-вставка "Bitmap Image" (класс `Paint.Picture`): 78-байтный
заголовок + BMP + 12-байтный хвост. Побайтовый round-trip совпал на всех
66 из 66 записей образца.

**Про размер**: BMP хранится без сжатия — одно фото занимает 1–10 МБ
(образец весит 174 МБ на 66 фото). У `.accdb`/`.mdb` жёсткий лимит
**2 ГБ на файл** — это около 700–750 карточек при таком среднем размере.
Используйте `--access-max-photo-dimension 800` (или другое значение),
чтобы ужимать фото по большей стороне перед упаковкой в BMP.

## Известная проблема с pyodbc: HY010 / SQLParamData

При вставке BLOB через `pyodbc` + драйвер Access встречалась ошибка
`HY010 Function sequence error (SQLParamData)`, особенно на больших фото.
**Решение — не вызывать `cursor.setinputsizes()`** перед `execute()`:
pyodbc сам корректно определяет большие `bytes`-параметры, а ручная
подсказка драйверу конфликтует с его собственной обработкой. Это уже
учтено в текущей версии скрипта (`insert_access_row` вызывает `execute`
напрямую, без `setinputsizes`). Если проблема всё же вернётся —
уменьшите фото через `--access-max-photo-dimension`, а если и это не
поможет — есть более радикальный вариант (разбить один `INSERT` с
несколькими параметрами на `INSERT` + отдельный `UPDATE` для фото),
напишите, поможем адаптировать.

## Оговорка про тестирование

Формат `[Фото]` проверен побайтовым round-trip на реальных данных — это
надёжно. Логика (что добавлять/пропускать, фильтры, `--only-page`
и т.п.) проверена через Linux-заглушку (mdbtools), которая умеет читать
`.accdb`, но не писать — саму операцию `INSERT` через настоящий
Windows-драйвер каждый раз проверяйте на **копии** файла, лучше сначала
`--dry-run`, затем вручную откройте копию в Access и посмотрите, что
несколько новых фото открываются нормально.

## Отчёт и коды возврата

- `0` — всё добавлено без проблем.
- `1` — не удалось начать вообще (файл/страница/человек не найдены, нет
  ни одной строки для добавления, не удалось подключиться к Access).
- `2` — найдены проблемы (повторяющееся ФИО, ошибка при вставке и т.п.).
  Без `--allow-partial` — не добавлено ничего; с ним — добавлено всё,
  кроме проблемных строк.
