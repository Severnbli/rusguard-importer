# rusguard.py

Импорт сотрудников/учащихся, ключей СКУД (`acskeys`) и карточных
фотографий в БД RusGuard (PostgreSQL) из Excel-файла.

## Установка

```bash
pip install -r requirements.txt
```

`rusguard.py` использует общий модуль `common.py` (страницы Excel, фото на
диске, общие флаги командной строки) — он должен лежать **в той же
папке**. Отдельно запускать `common.py` не нужно, он не самостоятелен.

## Структура Excel-файла

**Один лист — справочник должностей** (по умолчанию называется
`Должности`, см. `--sheet-positions`):

| № | Наименование | Айди |
|---|---|---|
| 1 | Учитель | 07b33b79-... |
| 2 | Учащийся | *(пусто)* |

`Айди` может быть пустым — тогда у всех с такой должностью
`employeepositionid` останется `NULL` (это не ошибка).

**Все остальные листы — «страницы» с людьми** (сотрудники, конкретный
класс и т.п.) — их может быть сколько угодно, каждая обрабатывается
независимо. Столбцы ищутся по заголовку (регистр не важен):

| № | ФИО | Номер карты | Карточка изготовлена | Карточка в системе | Должность | Путь к фото | Айди группы |
|---|---|---|---|---|---|---|---|
| 1 | Иванов Иван Иванович | 123456 | Да | Нет | Учитель | `C:\Data\employee` | 046ada11-... |

- **№** — порядковый номер человека на странице. Обязателен, должен быть
  **уникален в пределах страницы** (по нему сопоставляется файл фото).
- **ФИО** — «Фамилия Имя Отчество». Обязательно. **Если начинается с `#`
  — строка целиком пропускается** (как закомментированная).
- **Должность** — сверяется со справочником. Можно оставить пустым; если
  указано — должно там найтись (иначе ошибка данных).
- **Номер карты** — можно несколько через `,` `;` `/` или перенос строки.
  Необязательно.
- **Карточка в системе** — `Да`/`Нет`. **В БД импортируются только строки
  со значением `Нет`.** Обязательный столбец.
- **Айди группы** и **Путь к фото** — заполняются **один раз на всю
  страницу** (берётся первое непустое значение в столбце; если в разных
  строках указаны разные значения — это ошибка). Айди группы обязателен
  (`employeegroupid` — `NOT NULL`); путь к фото необязателен.

### Путь к фото и файлы

`Путь к фото` — это **папка**, а не файл. Если значение выглядит как
абсолютный путь Windows (с буквой диска, напр. `C:\Data\employee`, или
сетевой `\\server\...`) — используется как есть. Любое другое значение (в
т.ч. `/photos/employee`) считается **относительным к `--photos-root`**.

Файлы фото в папке должны называться `<№>.<расширение>` — `1.jpg`,
`2.png`, `15.bmp` и т.п. Поддерживаются jpg/jpeg/png/bmp/gif/tif/tiff/webp,
сравнение по числу (ведущие нули не важны). Если для номера найдено
несколько файлов с разными расширениями — используется первый по
алфавиту, об этом будет предупреждение. Файлы без соответствующей строки
на странице — тоже предупреждение (возможная нестыковка нумерации).

### Важно про столбец №, если он формула

Если `№` — это формула (`=A2+1`, автонумерация), скрипт читает
**закешированное значение**, которое в файл кладёт Excel/LibreOffice при
сохранении. Скрипт не пересчитывает формулы сам. Если файл когда-либо
пересохранён программно (не через реальный Excel/LibreOffice) без
пересчёта — кеш может отсутствовать, и № прочитается как пустой. Просто
откройте и пересохраните файл в Excel перед запуском, если сомневаетесь.

## Запуск

```bash
# проверка "на сухую"
python rusguard.py import.xlsm \
    --host 192.168.1.10 --dbname rusguard --user rg_import \
    --photos-root "C:\Data" --dry-run

# реальный импорт
python rusguard.py import.xlsm \
    --host 192.168.1.10 --dbname rusguard --user rg_import \
    --photos-root "C:\Data"
```

Пароль (по приоритету): `--password`/`--pass`, переменная `PGPASSWORD`,
иначе — интерактивный скрытый ввод.

### Выборочный запуск

```bash
# только одна страница
python rusguard.py import.xlsm ... --only-page "2А"

# только один человек на странице (по №)
python rusguard.py import.xlsm ... --only-page "2А" --only-person 5
```

`--only-person` без `--only-page` — ошибка (номера уникальны только в
пределах страницы, а не по всему файлу).

Полный список параметров: `python rusguard.py --help`.

## Что скрипт делает

- **employee** — ищет уже существующего (`isremoved = false`) человека по
  ФИО; при расхождении обновляет группу/должность; иначе создаёт. Можно
  запускать повторно — уже импортированные не задваиваются.
  `fullname`/`fullnamehash` считает сама БД триггером.
- **acskeys / acskey2employeeassignment** — создаёт/переиспользует карту,
  назначает сотруднику. Биометрические поля никогда не заполняются. Если
  номер карты уже активно назначен ДРУГОМУ — не трогает, только сообщает
  (решать вручную в RusGuard — вопрос физического доступа, автоматически
  такое не делаем).
- **employeephoto** — `employeeimagetype = 0` (обычное карточное фото).
  Биометрия (`employeebiometrics`, `employeefacevector` и т.п.) не
  затрагивается вообще.

## Режим «всё или ничего» (по умолчанию)

Если хотя бы одна из **подлежащих импорту** строк (см. фильтр «Карточка в
системе») не проходит проверку — в БД не сохраняется вообще ничего, даже
полностью корректные строки. Полный список проблем печатается за один
проход. `--allow-partial` отключает это: сохранить валидные, проблемные
пропустить.

## Отчёт и коды возврата

- `0` — всё прошло без ошибок и конфликтов, изменения сохранены.
- `1` — не удалось начать вообще (файл/страница/человек не найдены, нет
  ни одной строки для импорта, не удалось подключиться к БД).
- `2` — найдены проблемы (неизвестная должность, конфликт номера карты,
  неоднозначное ФИО, дубль № на странице и т.п.). Без `--allow-partial` —
  не сохранено ничего; с ним — сохранены только валидные строки.
